## 一、结束运行 = agent 系统工具 `finish_run`

### 为什么要它
原来的收尾是"模型输出一段纯文字 → 框架猜它说完没有"。猜错就注入"任务尚未完成，继续执行剩余步骤"，
最多推 3 次。日志实证：一次"检查积压"的定时唤醒被推到 **25 轮 / 388,240 token**。
让 agent 自己喊"我做完了"，比让框架猜可靠得多。

### 流程
```
agent 判断任务完成
   └─> 调用 finish_run(summary="…")
         ├─ agent.finish_requested = True；agent.finish_text = summary
         └─ Agent.step() 在工具执行后立刻检查该标志（在 tool 消息入栈之后）
               └─ 记一条 finish_run 日志，把 summary 作为本次运行的最终答复返回
```
**关键点**：检查点放在"工具执行循环内"而不是"轮末"，这样 finish_run 一调用就当轮收工，
不等审查钩子、不等 auto_continue 判定。

### 落地
- `core/agent.py`：新增 `finish_requested` / `finish_text`；工具执行后检查并 return
- `core/runner.py`：注册 `finish_run` 工具（`summary` 参数）
- `core/runner.py` PRIMARY_PROMPT：新增【收工纪律】——确认无事可做就主动 finish_run

### 与上一轮修复的关系
上一轮已修了完结判定漏判 + 加了空转刹车。`finish_run` 是**第三条防线**：
判定放宽（被动兜底）→ 空转刹车（被动兜底）→ **agent 主动收工（根治）**。

## 二、agent 可管理的唤醒黑名单 `wake_blacklist`

### 设计取舍
| 问题 | 取舍 |
|---|---|
| 存哪 | `config/wake_blacklist.json`（AI 专属文件，**不动操作者的 config.yaml**），仿照已有 `wake_words` |
| 何时生效 | daemon 每次聊天轮询按 **mtime** 重载，加词 ~2 秒内生效，重启保留 |
| 与 `noise_patterns` 的关系 | **并集**。noise_patterns 是操作者手配（agent 改不了）；黑名单是 agent 自管 |
| 命中效果 | 既不算 @提及（不误唤醒），也不计入待回应积压（不顶起定时唤醒） |
| 默认开关 | **默认开启**（这是防误唤醒的，风险低；不像唤醒词那样"让玩家能叫你"有社交风险） |

### ★三条红线（防 agent 把自己关进小黑屋）
1. 不得屏蔽 **bot 自己的名字**（否则对所有 @ 提及永久失聪）
2. 不得屏蔽 **操作者配置的 mention_extra 触发词**（不得覆盖操作者意图）
3. 拒绝通杀正则（`.*` `^.*$` `[\\s\\S]*` 等）

另：数量上限 20、正则 ≤120 字符、非法正则拒绝、每次增删记录触发源（审计）。

### 流程
```
agent: wake_blacklist(action=add, pattern="is now sleeping", note="睡觉进度广播")
   ├─ 校验：非空 / 长度 / 通杀 / 正则合法 / 红线 / 去重 / 上限
   └─ 原子写 config/wake_blacklist.json
daemon.poll_chat() 每次轮询
   └─ _refresh_wake_blacklist()（mtime 变了才重读，编译正则）
        └─ is_mention() 命中 → False（不唤醒）
           _is_noise()  命中 → True（不计积压）
```

### 落地
- `tools/builtin/wake_blacklist.py`（新）：`list / add / remove / test`
  （`test` 让 agent 加词前先试一条消息会不会被误伤）
- `core/daemon.py`：`_refresh_wake_blacklist()` / `_blacklisted()`，接入 `is_mention` 与 `_is_noise`
- `core/orchestrator.py`：注册工具，并传入 `protected = bot_names + mention_extra`
- `config/config.yaml`：`allow_ai_wake_blacklist: true` / `wake_blacklist_max: 20`

## 三、审查默认调用 LLM

改动很小但很关键：规则审查**查不出空转**——空转时所有工具调用都成功，R1（连续 3 次同操作失败）
和 R2（连续 6 次失败）永不触发。日志实证：`review_20261018.jsonl` 22 条 verdict **全为 null**。

- `config/config.yaml`：`review_llm: false` → **`true`**
- `core/daemon.py`：默认值 `dcfg.get("review_llm", False)` → **`True`**
- 同时**重写审查员提示词**，把"空转"列为一等公民：
  > ★空转（重点）：所有操作都成功，但只是在反复查询同一件事（反复读状态/聊天/记忆档）、
  > 没有任何改变世界的动作（移动/放置/挖掘/合成/对话），且已经输出过结论性汇报——
  > 这说明它早就没事干了，只是在被催着继续。这种情况判「停止」。

成本控制：仍是"规则全过才问 LLM"，且只发最近 N 条操作摘要，不是全文。

## 四、分层记忆（未总结 → 日 → 周 → 月 → 年）

### 目录结构
```
<shared>/docs/记忆/
  INDEX.md                          总索引（已补新结构说明）
  unsorted/                         ★未总结：一次唤醒一个文件
    2026-10-18_0411_manual.md       ← 命名：日期_时分_触发源
    2026-10-18_0342_scheduled.md
    _done/2026-10-18/               已汇总进日档的原件（归档）
  day/2026-10-18.md                 日档
  week/2026-W42.md                  周档
  month/2026-10.md                  月档
  year/2026.md                      年档
  raw/                              原始记录（不动）
```

### ★核心设计：框架搬文件，agent 只写内容
agent 连 delete 都没有，让它手工挪文件必然出错。所以：
- **框架负责**：建目录、给本次唤醒开文件（带元信息头部）、判断"该总结谁"、commit 后归档原件、记账
- **agent 负责**：读源材料 → 写日/周/月/年档 → 调 `memory(action=commit)` 收工

总结走 agent 自己的 LLM 上下文，**不额外开一次 LLM 调用**（省 token）。

### 到期推导（纯推导，无需定时器/常驻状态）
```
日 ：存在 unsorted 文件的日期 < 今天      → 过零点了，可总结那天
周 ：存在 ISO 周 < 当前周 的日档          → 那周结束了
月 ：存在月份 < 当前月的周档              → 那月结束了
年 ：存在年份 < 当前年的月档              → 那年结束了
已完成项记在 logs/memory_state.json，避免重复提醒
```

### ★一条重要修正：只有 day 层才归档源材料
初版设计把每层的源都搬走——那样"总结完一周"之后就再也查不到那几天的日档了。
**日档/周档/月档是成品明细档，必须原样保留**；只有 `unsorted/` 是中间态，汇总进日档后才归档。

### 完整流程
```
① 唤醒开始（run_task）
     memory.ensure_layout() 建目录骨架
     memory.unsorted_path() 定本次唤醒的文件名
     memory.open_note()     写元信息头部（时间/触发源/任务/当日第几次）
② 运行期间
     agent 随时 memory(action=note, text=…) 追加要点
③ 构建任务时（daemon._build_task）
     memory.pending() 推导到期项 → 0 token 插进任务：
     「【记忆整理·到期】…做法：pending 读源 → file_append 写目标档 → commit 提交」
④ agent 做总结
     memory(action=pending, kind=day, period=2026-10-18)  读源材料全文
     file_append 写到 记忆/day/2026-10-18.md
     memory(action=commit, kind=day, period=2026-10-18)
         ├─ 校验目标档已写且非空（<10 字符拒绝）
         ├─ 源材料移到 unsorted/_done/2026-10-18/
         └─ 记账 → 该周期不再出现在待办
⑤ 下次运行自动附带压缩记忆（_auto_memory_block）
     INDEX + 年档 + 月档 + 周档 + 昨日日档（≤4000 字符）
```

### 落地
- `core/memory.py`（新）：目录/命名/到期推导/commit/归档/状态
- `core/runner.py`：开本次唤醒文件、注册 `memory` 工具、改写 `_auto_memory_block`
- `core/daemon.py`：`_build_task` 插入到期提醒
- `core/runner.py` PRIMARY_PROMPT：新增【记忆纪律】三条
- **数据迁移**：既有扁平档已搬进新结构
  （`2026-10-1x*.md` → `day/`、`2026-10.md` → `month/`、`2026.md` → `year/`），INDEX.md 补结构说明

## 五、实机验证（04:11 控制台指令唤醒）

让 agent 依次用 `memory(status)` → `memory(note)` → `finish_run`：

```
round 1  memory(status)   → {"ok":true, "unsorted_n":1, "day_n":8, "week_n":0, "month_n":1, ...}
round 2  memory(note)     → 已追加到本次唤醒的未总结记忆
round 3  session_stats
round 4  finish_run       → [finish_run round_no=4]  ← 立即收工
task_end rounds=4 tokens=54669 elapsed=6.0
```

**对比改造前同类任务：25 轮 / 388,240 token / 69.8 秒 → 4 轮 / 54,669 token / 6.0 秒**
（轮数 −84%、token −86%、耗时 −91%）

未总结文件按次唤醒落盘已确认：
```
记忆/unsorted/2026-10-18_0411_manual.md
# 未总结记忆 · 2026-10-18 04:11 唤醒 #1
- 时间：2026-10-18 04:11:07 / 触发源：manual / 任务：…
```
