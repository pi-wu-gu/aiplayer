## 一、设计定稿（决策 → 参数）

### 1.1 锚点可调

环境检测的中心锚点不再固定脚部，三级可选：

| 档位 | 配置值 | 含义 |
|---|---|---|
| 脚部（默认） | `feet` | 玩家脚部所在方块（BlockPos containing pos） |
| 眼睛 | `eyes` | 眼睛所在方块（+1.62 偏移后取整） |
| 自定义 | `"dx,dy,dz"` | 相对脚部的方块偏移，如 `"0,-1,0"`=脚下一层 |

- 配置：`[watch].env_anchor`；动作参数 `anchor` 单次覆盖（如 `env_scan anchor=eyes`）
- 锚点同时是「移动超距触发」的参照：上次刷新时的玩家锚点位置 vs 当前锚点位置

### 1.2 A / B 范围均可调

| 功能 | 参数 | 默认 | 范围 | 管什么 |
|---|---|---|---|---|
| A 环境检测 | `env_range` | 5 | 1-15 | 检测立方体边长（格），5=5×5×5=125 格 |
| B 位置轨迹 | `pos_interval_ms` | 500 | 100-5000 | 采样间隔 |
| B 位置轨迹 | `pos_min_move` | 0.5 | 0-8 | 位移低于此值不记（静止零增长） |
| B 位置轨迹 | `pos_retention_ms` | 600000 | 60000-3600000 | 保留窗口（10 分钟） |
| B 位置轨迹 | `pos_query_limit` | 200 | 10-1000 | 单次查询返回条数上限 |
| 触发 | `env_move_refresh_dist` | 3.0 | 0.5-32 | 锚点移动超此距离 → 自动标脏（格） |
| 受击 | `hurt_retention_ms` | 600000 | 60000-3600000 | 攻击源采样记录保留窗口 |
| 采样 | `sample_base_fields` | pos,yaw,pitch,sneak | — | 全系统一基础三件套（1.6 规范，不可裁） |

二期参数（C/D）同表扩展：`entity_radius`（16）、`entity_interval_ms`（1000）、`entity_retention_ms`（600000）、`player_interval_ms`（1000）、`player_retention_ms`（600000）。

总闸：`[watch].enabled`（默认 true）+ `[watch].env_per_round`（默认 true，每轮注入开关）。

### 1.3 分类触发 + 脏标记（核心机制）

环境摘要分**四个类**，每类独立「上次值」缓存 + 独立脏标记：

| 类 | 内容 | 成本 | 脏判定 |
|---|---|---|---|
| `blocks` | 范围内方块聚合摘要（计数 + notable + 流体） | 低频扫描（每 20 tick）后与缓存摘要逐字节比对 | 摘要字符串 ≠ 缓存 → 标脏 |
| `moved` | 玩家锚点位移 | tick 级距离计算（O(1)） | dist(当前锚点, 上次刷新锚点) > `env_move_refresh_dist` → 标脏 |
| `self` | 位置/生命/维度/手持等 O(1) 状态 | 每次读取实时取 | **不参与脏标记，每读必返**（成本可忽略，且 agent 每轮都该知道） |
| `entities`（二期） | 附近实体计数/类型摘要 | 低频扫描后差分 | 计数或类型集合变化 → 标脏 |

**渲染规则**：注入时只渲染 changed 的类；全 unchanged → 注入单行「【环境快照】无变化」。

### 1.4 「一轮思考最多触发一次」的三道保证

1. **框架侧单点**：注入挂在 `Agent.step` 边界，一次 step 一次 `env_scan` 调用——物理上不可能一轮多次
2. **模组侧 read-to-clear**：`env_scan` 返回当前脏状态后**立即清零**——即使 agent 在一轮内罕见地重复调用（或主动窥视），第二次起全部 `unchanged`，零重复 token
3. **提示词约束**：PRIMARY_PROMPT 明示「环境快照由系统在每轮思考前自动注入，**不要主动调 env_scan**」——主动读只会读到空变化，纯浪费；想看即时全量用 `mc_state`/`entities`（那些无脏语义，是即时快照）

### 1.5 「不保存过期数据」三层落实（沿用可行性结论）

① 入队时时间戳淘汰（不是查询时过滤）② 全内存、不落盘 ③ 窗口参数可调——用户要更短就调更短。

### 1.6 采样数据规范（全体系统一，v0.10 用户增补）

**所有采样**（位置轨迹 / 玩家动态 / 玩家完整采样 / 攻击源采样）的**基础三件套必返**：

| 字段 | 说明 |
|---|---|
| `pos` [x,y,z] | 精确坐标 |
| `yaw`（+`pitch`） | 朝向（注意力方向） |
| `sneak` | 是否蹲下（减速/潜行/躲避的姿态信号） |

**可选字段**（按采样类型的 full 参数或字段开关返回）：`held`（手持 id+count）、`armor`（四槽）、`health`、`sprint`、`vehicle`、`effects`、`dim`、`ping`、`gamemode`。

- 设计理由：位置/朝向/蹲姿是「这个单位在做什么」的最小充分集；手持/装备信息量大且非常量，按需取
- ★`pos_track`（B）的条目按此规范补 `sneak` 字段（原设计 {t,pos,yaw,dim} → {t,pos,yaw,pitch,sneak,dim}）
- 采样开销：基础三件套全是 O(1) getter；`armor` 要遍历 4 槽、`effects` 遍历效果集合——只在 full 模式付这个成本

### 1.7 玩家完整采样（模型主动触发，应对极端需求）

与 env_scan 的「变化才推」互补：agent 判断需要**全量现状**时主动打一发。

```
{"type":"player_sample","name":"<PLAYER_A>","full":true}
→ {"ok":true,"players":[{"name":..,"pos":[..],"yaw":..,"pitch":..,"sneak":true,
    "sprint":false,"health":..,"held":{"id":..,"count":..},
    "armor":[{"slot":"head","id":..},…4槽],"dist":..,"gamemode":..,"ping":..}]}
```

- `name` 省略 = 附近全部玩家（默认 limit 20）；`name` 指定 = 精确一人
- `full`（默认 true）= 带可选字段；`full=false` = 只基础三件套 + dist
- 数据源：附近实体玩家（`level.getEntities` 的 Player 过滤）+ Tab 列表补 ping/gamemode
- 不设缓存、不设脏标记——主动触发=即时快照（与 mc_state/entities 同语义）

### 1.8 被攻击自动触发攻击源采样（事件驱动）

**触发源**：NeoForge `LivingDamageEvent`（玩家实体受伤瞬间，零延迟，不等 tick 采样周期）。

**采样内容**（入 hurt 缓冲）：

```json
{"id":N,"t":..,"damage":3.5,"type":"minecraft:arrow",
 "self":{"pos":[..],"yaw":..,"pitch":..,"sneak":false},
 "source":{"kind":"entity","id":812,"type":"minecraft:skeleton","name":"Skeleton",
           "pos":[..],"dist":17.2,"dir":"北偏东30°"},
 "after_health":16.5}
```

- `source.kind`：`entity`（生物/玩家/弹射物实体）/ `none`（无实体源：摔落/岩浆/窒息/掉虚空——`type` 字段给伤害类型）
- 缓冲 retention：`hurt_retention_ms`（默认 600000），入队淘汰同 B
- 读取：`hurt_log`（since 游标，同 pos_track 语义）
- 极端需求场景：被骷髅冷箭、被玩家偷袭——agent 下一轮醒来即可见「17 格外骷髅射了我 3.5 点血」

### 1.9 锁定视角到实体（look_lock target，v0.2.1.37 即时交付）

不依赖环境检测体系，与 face 同级的小功能扩展，**先行交付**：

```
{"type":"look_lock","target":812,"duration_ms":5000}              ← 按实体 id（entities 动作返回）
{"type":"look_lock","target_type":"minecraft:cow"}                ← 64 格内最近的一只
{"type":"look_lock","target":812,"aim":"eyes"}                    ← 瞄眼睛（默认 center=碰撞箱中心）
```

- 每 tick 按 id 重新取实体（`level.getEntity(id)`，id 稳定；不缓存实体对象防卸载/复用）
- 结束条件：`duration_end` / `interrupted`（同坐标模式）/ **`target_lost: 实体消失或死亡`** /
  **`target_lost: 实体超距(>8格)`**
- 与 `x,y,z`、`face` **互斥**（实体没有面的概念；偏瞄用 `aim`）；`target` 与 `target_type` 互斥
- 状态查询/墓碑回显 `target{id,type,aim}`；返回回显 `target{id,type,name,aim,dist}`
- 典型用途：盯着生物/玩家持续对准（移动战）、跟随拍摄、警惕某个方向

## 二、数据格式

### 2.1 `env_scan` 返回（一期）

```json
{"ok":true,
 "blocks":{"changed":true,"range":5,"anchor":"feet","center":[196,76,-1106],
           "counts":{"minecraft:air":98,"minecraft:stone":12},
           "notable":[{"id":"minecraft:chest","pos":[198,77,-1103]}],
           "fluid":[]},
 "moved":{"changed":true,"from":[192,77,-1106],"dist":6.2},
 "self":{"pos":[196.5,77.0,-1105.5],"health":20.0,"dim":"minecraft:overworld","held":"minecraft:diamond_pickaxe"},
 "cleared":["blocks","moved"]}
```

- `cleared` = 本次读取后被清零的脏类（read-to-clear 的显式回执）
- unchanged 的类只回 `{"changed":false}`，不带数据

### 2.2 每轮注入渲染（agent 侧）

```
【环境快照·变化】方块(5×5×5,锚点=脚部): air×98 stone×12 grass×6 | notable: chest@(198,77,-1103)
  | 位移: 距上次刷新 6.2 格 | 自身: (196.5,77,-1105.5) HP20 持 diamond_pickaxe
```

全无变化时：

```
【环境快照】无变化（方块/位移与上轮相同）
```

- 设计目标：changed 轮 ~100-150 token，unchanged 轮 ~15 token；12 轮混合场景 1-1.5K token
- ★**禁全量平铺**：125 个方块 id 逐格列出 = 700 token/轮的浪费模式，实现评审时卡死

### 2.3 `pos_track` 查询（B）

```
{"type":"pos_track","since":<id>,"limit":200}
→ {"ok":true,"entries":[{"id":N,"t":..,"pos":[x,y,z],"yaw":..,"pitch":..,"sneak":false,"dim":..}],
   "next_id":N,"retention_ms":600000}
```

游标语义与 `/chat` 一致（since=上次 next_id 只取新的）。★条目含采样规范基础三件套（pos/yaw/pitch/sneak，见 1.6）。

## 四、验证计划

### 4.1 离线（构建时）

| 用例 | 期望 |
|---|---|
| 摘要聚合 | 125 格 → counts 5-15 种 + notable 单列；禁全量平铺（断言输出长度上限） |
| 脏标记 | 方块变→dirty；位移 0→不脏；超距→dirty；读取→清零 |
| 重复读 | 连读两次，第二次全 unchanged 且 `cleared:[]` |
| 静止轨迹 | 站定 60s → 0 条新记录 |
| 过期淘汰 | 超 retention 的条目查询不到（入队时已丢，非过滤） |

### 4.2 实网（服务器恢复后）

1. 进世界 → 等 daemon 唤醒或手动任务，数日志确认每轮恰 1 次 env_scan
2. 站定 3 轮 → 第 2、3 轮注入「无变化」单行（token 增量 ≈0）
3. 挖一块方块 → 下一轮 blocks.changed=true 且 counts 反映
4. 移动 8 格（>3 格阈值）→ 下一轮 moved.changed=true
5. 移动 1 格（<阈值）→ moved unchanged
6. `env_scan anchor=eyes range=3` 单次覆盖 → 返回按眼睛锚点 3×3×3
7. `pos_track` 全程游标读 → 条目数 ≈ 移动时长/0.5s × 位移过滤后
8. 12 轮任务总 token 增量 < 2K（否则压缩摘要格式）

## 五、风险与边界

| 项 | 对策 |
|---|---|
| token 超支 | 聚合摘要 + unchanged 单行 + read-to-clear；4.2-8 是验收硬指标 |
| tick 性能 | 扫描降频（20 tick）；距离检测 O(1)；实体农场场景压测 |
| 与「截图仅可调用功能」约定的边界 | 环境检测是用户明确要求的每轮自动注入（新指令），且仅文本不涉图像；保留 `env_per_round=false` 一键关回——**在 README 明示此边界变化** |
| 二期实体差分正确性 | 实体卸载≠消失（宽限 N tick）；Entity.getId() 跨区块卸载后会复用（id 复用误判 appeared）——二期专项 |
| 受击事件选型 | `LivingDamageEvent`（NeoForge 21.1 可用；服务端/客户端双侧都会发，客户端侧只采样不同步发包，避免回环）；弹射物类攻击源的 `getDirectEntity()`/`getEntity()` 要分清（箭 vs 骷髅） |
| look_lock 实体的 id 时效 | target id 来自 entities 动作快照，实体卸载后 id 失效 → `target_lost` 报错文案要提示重新查；不缓存实体对象（防复用误跟） |
| 配置漂移 | 三源（toml 注释/config.yaml/配置说明.md）同步进阶段 4 |

## 六、明确不做（排除项）

- 不做方块**全量**列表注入（禁平铺）
- 不做跨重启持久化（全内存，重启即空——位置/动态历史跨会话无意义）
- 不做 entities 类的即时快照进 env_scan 一期（那是 `entities` 动作的既有职责；entities 类摘要二期上）
- 不做 agent 主动刷新环境通道（read-to-clear 语义下主动读无收益，提示词明禁）；**例外**：`player_sample` 是明确授权的主动全量采样（1.7），`mc_state`/`entities` 即时快照不受限
- 不做 player_sample 的落盘/历史（主动触发=即时语义，要历史用 pos_track/player_track）
