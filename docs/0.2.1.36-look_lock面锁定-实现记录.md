# look_lock 面锁定 face 实现记录（v0.2.1.36）

- **日期**：2026-10-18
- **需求**：给视角锁定到方块的功能添加可选锁定面选择功能
- **结论**：已实现并部署。面中心计算在 `Actions.lookLock`（纯数学、无副作用），维持/中断机制零改动；实网六面测试被 <SERVER> 服务器不可用阻塞（见「验证状态」）。

## 一、设计

### 参数
```
{"type":"look_lock","x":196,"y":76,"z":-1106,"face":"up","duration_ms":5000}
→ {"ok":true,"result":"look_lock_started","aim":[196.5,77.0,-1105.5],"face":"up","yaw":…,"pitch":…}
```

- `face` 可选：`up`/`down`/`north`/`south`/`east`/`west`；别名 `top`→up、`bottom`→down；
  `center`/`auto`/省略 = 默认瞄方块中心
- **只对整数方块坐标有效**：小数坐标 = 精确点模式，与 face 二选一（同时给非 center 的 face 报错）
  ——不引入「小数坐标+面」的歧义语义（面是方块的属性，不是点的属性）

### 面中心偏移表（`Actions.FACE_OFFSETS`）

| face | 偏移 | 瞄准点（方块 196,76,-1106） |
|---|---|---|
| center（默认） | (+.5,+.5,+.5) | (196.5, 76.5, -1105.5) |
| up / top | (+.5,+1,+.5) | (196.5, 77.0, -1105.5) |
| down / bottom | (+.5,0,+.5) | (196.5, 76.0, -1105.5) |
| north | (+.5,+.5,0) | (196.5, 76.5, -1106.0) |
| south | (+.5,+.5,+1) | (196.5, 76.5, -1105.0) |
| east | (+1,+.5,+.5) | (197.0, 76.5, -1105.5) |
| west | (0,+.5,+.5) | (196.0, 76.5, -1105.5) |

## 二、实现要点

1. **面中心计算放在 Actions 层，Drivers 层零机制改动**：`startLookLock` 收到的就是最终瞄准点
   （tx/ty/tz），tick 维持每 tick 重算 yawPitch——移动中自动跟随的既有能力原样惠及面锁定。
   `LockTask` 仅加一个 `face` 字段用于状态回显。
2. **`normalizeFace` 归一化**：trim + 小写 + 别名表 + 白名单校验；未知值返回 null → 调用方报错
   （错误文案列出全部合法值）。
3. **顺带修复**：`look_lock` 无参查询原本排在 `requirePlayer()` 之后——离线/主菜单态查墓碑被拒。
   查询分支提前（墓碑查询不要求玩家在场，daemon 断线时也能看到上次锁定为何结束）。
4. **自省同步**：`actionsList()` 视角组描述补 face 规则（register 与展示表两套东西的纪律，
   见 2026-10-17 工具检查报告问题 1）。

# 追加：look_lock 实体锁定 target（v0.2.1.37，2026-10-18）

## 参数

```
{"type":"look_lock","target":812}                          ← 按实体 id（entities 动作返回）
{"type":"look_lock","target_type":"minecraft:cow"}         ← 64 格内最近的一只
{"type":"look_lock","target":812,"aim":"eyes"}             ← 瞄眼睛（默认 center=碰撞箱中心）
```

## 设计要点

1. **LockTask 加 targetEntityId（-1=静态点）/targetType/targetAim**；tickLookLock 里实体分支每 tick
   `level.getEntity(id)` 重取（**不缓存实体对象**——实体可能被卸载/复用，id 才是稳定键）
2. **aim 点**：`center`=（x, y+bbHeight/2, z）；`eyes`=（x, getEyeY(), z）
3. **结束条件新增**：`target_lost: 实体消失或死亡` / `target_lost: 实体超距(>8格)`（MAX_LOCK_REACH=8）
4. **互斥规则**：target/target_type 二选一；与 x,y,z 互斥；与 face 互斥（实体没有面的概念）
5. `target_type` 模式锁「发起时最近的一个」后转 id 跟踪（不随更近个体切换，防抖动）

# 追加：entities 输出 id + 直锁类型回填（v0.2.1.38，2026-10-18）

## 背景

0.2.1.37 实网测试暴露：`look_lock target=<id>` 模式的报错提示引导 agent"用 entities 动作拿有效 id"，
但 entities 当时只返回 type/dist/pos——**id 无处可拿**，直锁模式对 agent 不可用。另发现 id 直锁时
查询回显 `type:"null"`（LockTask.targetType 未赋值，Json.str(null) 序列化成字符串 "null"）。

## 改动

1. `Actions.entities()`：每个实体项新增 `Json.kv("id", Json.num(e.getId()))`（置于 type 前）
2. `Drivers.startLookLockEntity()`：id 直锁模式回填真实类型
   `String resolvedType = typeId != null ? typeId : entityTypeId(e);` → LockTask 用 resolvedType
   （查询/墓碑分支原有的 null 防御保留作双保险）
3. 版本 0.2.1.37 → 0.2.1.38；bundle 重打（206 条目）；README / 动作备忘 / mc_bridge.py /
   PRIMARY_PROMPT 同步（entities 每项含 id/type/dist/pos，id 供 target 直锁）
